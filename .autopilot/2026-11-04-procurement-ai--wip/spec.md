# Спецификация: ИИ-система планирования закупок

## Задача

«Каждый месяц закупщики анализируют ассортимент и планируют новые закупки… Сейчас этот процесс занимает много времени»: товар едет из Азии 4–6 месяцев, поэтому решение принимается по прогнозу спроса, а не по текущим продажам. Нужно учесть сезонность (обогреватели — октябрь, триммеры — май, смесители — ровно), остатки, товар в пути, надёжность поставщика и наценку. Ошибка дорогая: не заказали — полгода дефицита, перезаказали — склад забит.

## Решение

Система, которую запускают по расписанию, по новым данным или по запросу. Она читает 6 CSV-выгрузок ERP и выдаёт:
- **дашборд** (публичная ссылка GitHub Pages, по-русски): что заказать сейчас, сколько, у какого поставщика, когда следующий заказ, на сколько хватит запасов, где риск дефицита или излишка, что на пересмотр цены, что мёртвый ассортимент, насколько точен прогноз, что изменилось с прошлого прогона, и записку ИИ-аналитика;
- **заказы поставщикам** — готовые списки с выгрузкой в Excel/CSV;
- **дайджест в Telegram** после планового прогона;
- **скилл Claude Code `/zakupki`** — пересчитать и разобрать результат вопросами («почему по SKU-X 400 шт?»);
- **видео** 5–7 мин с синтезированной озвучкой о том, как система устроена и как собрана.

Числа считает детерминированный Python, LLM (DeepSeek) только пишет пояснения к уже посчитанным числам.

## Решения по реализации

- **Python 3.12 + pandas/numpy**, пакет `procurement/` — данные небольшие (37 тыс. строк), всё в памяти; никаких БД.
- **Модель спроса — сезонная декомпозиция + тренд + цензура дефицита**, а не ML/Prophet: 5 сезонных циклов, ряды короткие и прерывистые; простая модель объяснима закупщику и проверяется бэктестом. Прогноз — 18 мес помесячно, внутри месяца равномерно (дневная шкала для дат).
- **Политика заказа — order-up-to с пересмотром раз в месяц**: стандарт для длинного плеча и сезонного спроса.
- **Сайт — статический**: Python пишет `site/data/*.json` + `index.html` (шаблон Jinja2), фронт — ванильный JS + ECharts (файл в репо, без CDN), Excel — SheetJS в браузере или заранее сгенерированные `.xlsx` (openpyxl) — генерируем заранее, проще и надёжнее.
- **LLM — DeepSeek** через OpenAI-совместимый API (`https://api.deepseek.com`, `deepseek-chat`, ключ `DEEPSEEK_API_KEY`), `requests`, без SDK.
- **Хостинг — публичный репозиторий GitHub `procurement-ai` + Pages из Actions** (деплой артефактом, не веткой).
- **Конфиг — `config.toml`** (tomllib из стандартной библиотеки).
- **Видео — edge-tts + ffmpeg** (захват экрана gdigrab, склейка, субтитры).

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Разбивка спроса по каналам | в данных нет (README) |
| Денежная оценка заказа и бюджет | денег в данных нет, только наценка и дециль |
| Расчёт контейнеров по объёму | веса нет у 784 из 791 SKU, объёма нет вовсе — показываем вес там, где есть |
| Подключение к ERP напрямую | вход — те же CSV-выгрузки; адаптер к ERP — следующий шаг |
| Авторизация на дашборде | публичная ссылка по решению Q1-а, данные обезличены |

## Открытые места

- `DEEPSEEK_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — вводит пользователь в секреты GitHub (и в `.env` локально). До этого записка ИИ и дайджест не появятся, всё остальное работает.
- Создание публичного репозитория, включение Pages, запись экрана — после отдельного «да».
